# Architecture

This directory documents the system architecture and the boundaries between its components.

Architecture documentation should describe the current implemented state separately from planned evolution. Suitable topics include:

- System context and component responsibilities.
- Kubernetes deployment topology.
- Telemetry generation, collection, processing, and storage flows.
- Grafana provisioning and observability resource ownership.
- Demo application dependencies and communication paths.
- Security, resource, and local development constraints.

Significant choices that explain why the architecture takes a particular form should be recorded as ADRs under `docs/decisions/` rather than embedded only in diagrams or overview documents.
